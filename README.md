# PRISM — Predictor and Indicator Sequential Monitoring

Reproducibility package for *PRISM: A Covariate-Driven Bayesian Online Changepoint
Framework for Anticipating Loss-Cost Trend Inflections* (2026 CAS Ratemaking Call Paper).

This package contains the complete simulation code, result artifacts, and figure
generators behind every number reported in the paper and its annexures. Appendix C of
the paper is a number-to-code map; this README is its companion from the other
direction — it documents what each file does, what seeds it uses, and which claim it
backs.

---

## 1. Data statement

**All data in this package is synthetic** and generated by `prism_sim.py` from fixed
seeds. No real policyholder data, claims data, or proprietary carrier experience is used
anywhere in this package.

The synthetic panels are calibrated to published stylized facts of long-tailed commercial
casualty — pre-inflection severity log-growth of roughly 3.4% per year, post-inflection
roughly 7.8%, and a quarterly log-return standard deviation of 1.6%. Calibration is not
asserted; it is tested. `tests.py` runs a Kolmogorov–Smirnov test on pooled
pre-inflection log-returns against the target Normal and fails the build if it rejects.

Because the data is synthetic, the results in this paper establish that the method
behaves as claimed under a known data-generating process. They do not establish
performance on real claims experience. That limitation is stated explicitly in the paper
and is not hedged here.

## 2. What PRISM does

Classical Bayesian Online Changepoint Detection (BOCPD; Adams & MacKay, 2007) maintains a
posterior over the **run length** *r*ₜ — the number of periods since the last
changepoint — and splits probability each step between a *growth* move (*r* → *r*+1) and a
*changepoint* move (*r* → 0). The split is governed by the **hazard**, which in the
original formulation is a constant.

PRISM replaces that constant with a covariate-driven hazard:

```
h(t | z_t) = sigmoid(alpha + beta' z_t)
```

where `z_t` concatenates two standardized streams the actuary already has:

- **External leading indicators** — noisy series that lead the inflection. In the
  synthetic study there are four, with a two-quarter lead, a peak z-score of 1.2, and
  unit noise. They are deliberately *not* oracles.
- **Internal predictor-stability signals** — computed from a baseline pricing model
  frozen on pre-cutoff data: S1 coefficient/fit drift, S2 residual autocorrelation
  structure, and S3 predictor-importance ranking distance (Kendall tau). Each is
  z-scored against an in-control reference distribution built from no-inflection panels.

The hazard intercept is set so that `sigmoid(alpha) = h0` when covariates sit at their
in-control means, which makes PRISM reduce exactly to constant-hazard BOCPD when the
hazard weights are zero. That reduction is enforced as a test, not assumed.

PRISM monitors either channel:

| Channel | Within-segment model (UPM) | Observation |
|---|---|---|
| `severity` | Gaussian, known variance (NIG special case) | severity log-return |
| `frequency` | Poisson–Gamma with exposure offset | claim count *N*ₜ, exposure *E*ₜ |

The inflection quarter *K* is a free parameter; the package tests *K* ∈ {16, 24, 30}.

**Alarm rule.** `A_t = P(r_t < r_star) >= tau`, with `r_star = 4` and `tau = 0.50`. A
short run-length posterior means the detector believes the current regime is young — that
is, that something recently changed.

## 5. Reproducing every number

```
python run_all.py      # regenerates results/ and figures/, prints the SHA-256 hash
python tests.py        # five falsifiable correctness checks
```

Approximate single-core runtimes:

| Command | Time |
|---|---|
| `python tests.py` | ~7 s |
| `python run_all.py` | ~3 min |
| all six extensions | ~1.5 min |

### What `run_all.py` does, in order

1. **Primary Monte Carlo.** For each channel (`severity`, `frequency`) and each scenario
   (`abrupt`, `gradual`), 1,000 paired replications across all four hazard variants —
   `severity_only`, `external_only`, `internal_only`, `prism`. Master seed 1000. Writes
   the 16,000-row run-level table to `results/prism_results.csv` and Wilson-interval
   aggregates to `results/summary.json`.
2. **Calibration.** Pools pre-inflection log-returns from 300 no-inflection panels
   (seeds 700000–700299) and runs a KS test against the target Normal.
3. **Reproducibility hash.** SHA-256 over the canonical results table.
4. **Supplementary analyses.** All twelve `extra_analyses.py` functions.
5. **Figures.** All six PNGs.

Because every run is paired on the `run` column, the McNemar, Wilcoxon and bootstrap
statistics in §4.2 are recomputable directly from `prism_results.csv` without rerunning
the simulation.

### Verification

On a faithful environment the canonical results hash is:

```
9058b0c9e313023c2c3f897bfcad2eeac7e7b914253fea10d1232787d81a77e2
```

A matching hash means the 16,000-run primary table regenerated bit-for-bit. Verified on
Python 3.12 / numpy 2.4 / scipy 1.17 / pandas 3.0, so the result is not fragile to
dependency versions well above the pinned minimums.

## 6. Configuration reference

Every design choice is fixed in the frozen `Config` dataclass in `prism_sim.py` before
any result is computed. Nothing is tuned to the outcome.

| Parameter | Value | Meaning |
|---|---|---|
| `T` | 40 | panel length in quarters |
| `K` | 24 | inflection quarter (free parameter) |
| `B` | 16 | pre-cutoff quarters used to freeze the baseline pricing model |
| `channel` | `"severity"` | which channel inflects and is monitored |
| `sev0` | 15000.0 | starting severity |
| `g0` | 0.0085 | pre-inflection severity log-growth (~3.4%/yr) |
| `g1` | 0.0190 | post-inflection severity log-growth (~7.8%/yr) |
| `sig_d` | 0.016 | sd of severity log-returns |
| `jump` | 0.085 | abrupt one-time severity log-jump at *K* |
| `ramp` | 8 | quarters over which a gradual inflection ramps `g0` → `g1` |
| `exp_g`, `exp_sd` | 0.008, 0.0015 | exposure growth and noise |
| `freq0` | 0.06 | baseline claim frequency per unit exposure |
| `freq_g0`, `freq_g1` | 0.005, 0.018 | pre/post frequency log-growth |
| `freq_jump` | 0.16 | abrupt frequency log-jump at *K* |
| `n_ind` | 4 | number of external indicators |
| `ind_lead` | 2 | quarters by which indicators lead the inflection |
| `ind_peak` | 1.2 | peak indicator z-score |
| `ind_noise` | 1.0 | indicator noise sd |
| `ind_decay` | 6 | indicator decay horizon |
| `h0` | 0.04 | baseline hazard; `alpha = logit(h0)` |
| `beta_ext`, `beta_int` | 1.0, 1.0 | hazard weights — **pre-set, not tuned** |
| `r_star` | 4 | run-length threshold in the alarm rule |
| `tau` | 0.50 | posterior-mass alarm threshold |
| `win_roll` | 6 | rolling window for internal signals |
| `nig_kappa`, `nig_a` | 1.0, 2.0 | severity UPM prior |
| `gam_a`, `gam_b` | 60.0, 1000.0 | frequency Poisson–Gamma rate prior |

The hazard weights deserve emphasis: `beta_ext = beta_int = 1.0` is a declared value, not
a fitted one. No grid search was run to select it, and the paper's §4.4(4) separately
shows that the *baseline's* hazard was already near-optimal at `h0 = 0.04`, so the
comparison is not rigged by giving PRISM a tuned parameter the baseline lacks.

## 9. Draft-2 extensions (Annexure C)

```
python prism_ext.py e1 e2 e3 e3b e4 e5
```

| Key | Function | Default size | Seeds | Output |
|---|---|---|---|---|
| `e1` | `e1_nig_severity` | n = 400 | 5000+, 860000+ | `ext_e1_nig.json` |
| `e2` | `e2_corroboration` | n = 400 | 5000+, 860000+, 12000+ | `ext_e2_corroboration.json` |
| `e3` | `e3_empirical_bayes` | 6 lines × 25 panels | 30000+, 70000+, 880000+ | `ext_e3_empirical_bayes.json` |
| `e3b` | `e3b_decision_calibration` | 4 lines × 40 panels | 40000+, 890000+ | `ext_e3b_decision.json` |
| `e4` | `e4_calibration` | n = 500, 10 bins | 50000+ | `ext_e4_calibration.json` |
| `e5` | `e5_joint_channels` | n = 400 | 60000+, 870000+ | `ext_e5_joint.json` |

- **E1** replaces the known-variance Gaussian UPM with the full Normal-Inverse-Gamma
  conjugate, under both Gaussian and heavy-tailed (t₄) severity.
- **E2** adds a corroboration gate requiring both streams to agree above a z threshold
  before an alarm is admitted, trading detection for specificity.
- **E3 / E3b** calibrate the hazard weight β by empirical Bayes and by explicit decision
  theory under a false-alarm cost λ.
- **E4** assesses whether the run-length posterior is *calibrated*, not merely
  discriminating: reliability bins, expected calibration error, Brier score, AUC.
- **E5** runs frequency and severity as a joint recursion rather than two separate
  monitors.

`prism_ext.py` imports from `prism_sim.py` but never modifies it, so no Draft-2 extension
can perturb a Draft-1 number.

## 11. Tests (falsifiable properties)

| # | Property | What failure would mean |
|---|---|---|
| 1 | **Calibration** — pre-inflection log-returns match N(g0, σ²); KS does not reject. | The synthetic panel is not what the paper says it is. |
| 2 | **β = 0 reduction** — PRISM with zero hazard weights equals constant-hazard BOCPD to < 1e-9. | The covariate hazard is doing something other than what the derivation claims. |
| 3 | **Validity** — the alarm statistic is a probability in [0,1] at every step. | The recursion is not a valid posterior. |
| 4 | **Frequency channel** — PRISM beats the loss-only monitor on a gradual frequency inflection. | The method is severity-specific, contrary to the paper. |
| 5 | **Arbitrary inflection point** — holds for *K* ∈ {16, 30}. | The result is an artifact of placing the change at quarter 24. |

Observed on a clean run: calibration mean 0.00839, sd 0.01593, KS p = 0.363; β = 0
reduction max deviation 3.33e-16.

## 12. Scope and limitations

- Synthetic data only. No claim is made about real claims experience.
- The Gaussian severity UPM assumes known variance in Draft 1; E1 relaxes this and shows
  the relaxation is not free — it raises detection and false alarms together.
- Hazard coefficients are declared, not identified from data. E3 and E3b explore what
  calibrating them would look like, but identification remains limited.
- PRISM's advantage is regime-dependent and the paper reports it that way: against an
  abrupt shock the covariates add nothing, and the gain is concentrated in the gradual
  case.
- The human-in-the-loop protocol is a design commitment, not a tested property of this
  code. Conditions under which it can fail are discussed in the paper, not simulated here.
